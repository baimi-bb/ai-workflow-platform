### 9. 为 Agent 增加受控联网能力
- 在 `backend/app/services/agent_execution_service.py` 中新增了两类后端工具：
  - `web_search`：用于按关键词搜索网页结果
  - `fetch_url`：用于抓取指定网页正文文本
- 这两个工具不是让模型直接自由联网，而是由服务端按受控协议代执行，再把结果回填给模型继续完成任务

### 10. Agent 执行链支持多轮“请求工具 -> 回填结果 -> 最终输出”
- 扩展了 agent 执行协议：模型现在可以先返回 `tool_calls`
- 后端会解析 `tool_calls`、执行工具、整理结果，并再次把结果交给模型
- 在达到最终回答后，仍然沿用现有的 `summary + files` 输出协议，不影响原来的文件写入逻辑

### 11. 增加联网能力的安全边界与配置项
- 在 `backend/app/core/config.py` 中新增联网相关配置：
  - `BACKEND_AGENT_WEB_ENABLED`
  - `BACKEND_AGENT_WEB_MAX_ITERATIONS`
  - `BACKEND_AGENT_WEB_SEARCH_MAX_RESULTS`
  - `BACKEND_AGENT_WEB_FETCH_MAX_CHARS`
- 默认限制了最大搜索结果数、单页正文长度和工具调用轮数，避免 agent 无限请求联网工具
- `fetch_url` 仅允许 `http` / `https` 链接

### 12. 执行结果中记录联网工具结果
- `task_run.output_payload` 新增 `tool_results`
- 这样后续在前端或排障时，可以直接看到 agent 这次执行过程中调用了哪些联网工具，以及返回了什么结果

### 26. 修复 Agent 直接返回工具请求对象却被标记为 completed 的问题
- 发现有些模型响应不是 `{"summary":"...","files":[]}` 这类最终结果
- 而是直接返回单个工具请求对象，例如：
  - `{"tool":"web_search","query":"...","max_results":5}`
- 这种内容本质上仍然是“中间态”，之前却会被当成最终输出写入 `task_run.output_payload`
- 从而导致 task run 被错误标记为 `completed`，workflow 继续向下推进

### 27. 增加最终输出严格校验
- 在 `backend/app/services/agent_execution_service.py` 中新增 `_validate_final_response_payload`
- 现在最终输出必须满足：
  - 不能是单个 `tool` 请求对象
  - 不能仍然包含 `tool_calls`
  - 必须带合法的 `files` 数组
  - 如果有 `summary`，必须是字符串
- 不满足时直接按执行失败处理，而不是继续当作成功结果

### 28. 修复最终输出校验失败时状态没有落成 failed 的问题
- 原先 `_apply_file_operations` 内部抛出的校验异常，没有统一回写 task run / workflow run 失败状态
- 现已补上异常兜底
- 所以像“只返回 `web_search` 请求”的情况，现在会正确变成：
  - task run = `failed`
  - workflow run = `failed`
- 不会再显示成 completed

### 29. 测试补充
- 更新 `backend/tests/services/test_agent_execution_service.py`
- 新增覆盖：
  - 单个工具请求对象可被识别为工具请求
  - 最终输出校验会拒绝单个 `tool` 请求对象
  - 最终输出校验会拒绝带 `tool_calls` 的伪最终结果
  - `execute_task_run` 遇到这种情况时会正确写回 `failed`

## 本次追加

### 22. 修复 Agent 联网后中间 JSON 被误当成最终输出的问题
- 发现当模型在联网多轮执行后，把“上一轮带 `tool_calls` 的 JSON”和“本轮最终 JSON”连续输出时
- 原来的解析只会尝试把整段文本当成一个 JSON 解析
- 一旦失败，就会把整段原样当成普通文本返回，导致：
  - task 被错误标记为 `completed`
  - Output 区域直接出现 `tool_calls` JSON 片段
  - downstream task 会把这个半成品结果当成已完成前置继续推进

### 23. 调整 Agent 响应解析策略
- 在 `backend/app/services/agent_execution_service.py` 中新增多 JSON 提取逻辑
- 现在会从模型响应里提取多个 JSON 对象，并优先采用最后一个 JSON 作为最终结果
- 对于联网 roundtrip，在识别到最终阶段没有 `tool_calls` 时，会将最后一个 JSON 规范化后再返回给落库层
- 这样即使模型把“上一轮 JSON + 最终 JSON”一起吐回来，也不会再把中间工具请求误显示为最终输出

### 24. 测试补充
- 更新 `backend/tests/services/test_agent_execution_service.py`
- 新增覆盖：
  - 连续多个 JSON 时优先取最后一个
  - 联网 roundtrip 遇到“前一个工具请求 JSON + 后一个最终 JSON”时，最终仍能正确落到最终结果
