### 46. 增加整条 Workflow Run 的自动执行入口
- 后端新增执行整条 workflow run 的接口：
  - `POST /workspaces/{workspace_id}/projects/{project_id}/runs/{workflow_run_id}/execute`
- 前端在 workflow run 详情区增加了“执行整个 Workflow”按钮
- 现在可以在创建 run 后，直接从当前 run 开始自动推进整条流程

### 47. Workflow Run 创建时补齐默认依赖规则
- 对普通任务节点：
  - 如果没有显式前置依赖，则默认依赖 `start` 节点
- 对 `end` 节点：
  - 默认依赖所有“没有后置依赖”的任务节点
- 如果项目里没有普通任务节点，则 `end` 会退化为依赖 `start`
- 这些依赖会写入 `task_run.task_dependencies_snapshot`，保证运行态快照稳定

### 48. Start / End 节点支持自动推进
- `start` 和 `end` 节点现在既可以只是边界节点，也可以真正执行任务
- 规则是：
  - 如果分配了 Agent，则会像普通节点一样进入调度执行
  - 如果没有分配 Agent，则会在满足条件后自动完成
- 因此空的 `start/end` 不会卡住 workflow，但有 Agent 的 `start/end` 也可以执行实际工作

### 49. 增加整条 Workflow 的自动调度循环
- 执行整条 run 时，系统会从当前状态持续推进：
  - 已完成节点会释放后继节点
  - 所有前置依赖完成的节点会自动进入可执行状态
  - 可执行节点会按优先级和入队时间排序后依次执行
  - 当 `end` 节点完成后，整个 workflow run 标记为 `completed`

### 50. Agent 忙时进入排队
- 当某个 ready 节点需要执行，但分配的 Agent 正在执行别的 task_run 时：
  - 该节点不会报错退出
  - 当前 workflow run 会进入 `queued`
  - 下次继续执行整条 run 时，会按队列顺序继续尝试
- 当前队列顺序规则：
  - 先按任务优先级：`high > medium > low`
  - 同优先级下按进入 ready 队列的时间顺序
